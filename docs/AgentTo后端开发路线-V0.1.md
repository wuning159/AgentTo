# AgentTo 后端开发路线 V0.1

> 文档状态：开发规划稿  
> 更新时间：2026-07-16  
> 用途：明确后端建设顺序、每一阶段的边界和验收条件  
> 说明：本路线不提前固化总经办尚未确认的流程规则。开发按阶段推进，每完成一阶段并确认后，再进入下一阶段。

## 1. 当前开发顺序

后端先建设 Agent 能力，再接正式工作流。这样安排不是忽略工作流，而是先把不依赖具体流转规则的能力做稳，包括文件、版本、上下文、Prompt、模型调用、Agent 运行和全过程记录。

整体顺序如下：

1. 校正后端基础环境；
2. 建设账号、文件任务和不可变版本；
3. 接通独立 RAG 服务并保存正式解析快照；
4. 建设模型、Prompt 和 Agent 定义管理；
5. 建设动态上下文和 Agent Runtime；
6. 建设 Agent 运行可视化和人工反馈；
7. 接入临时流程适配层；
8. 重构 HopFresh BPM，形成独立工作流服务；
9. 根据总经办最终确认结果调整 BPMN 和流转规则。

每一阶段都应形成可独立验证的结果。某一阶段没有通过测试或人工确认，不继续向后堆功能。

## 2. 已确定的技术基线

| 项目 | 当前选择 | 说明 |
|---|---|---|
| Java | Java 21 | 后端统一运行版本 |
| 后端框架 | Spring Boot 4.0.x | 第一版固定在 4.0 维护线，后续单独评估 4.1 升级 |
| Agent 框架 | Spring AI 2.0.0 | 负责模型抽象、Prompt、工具调用及后续 Agent 能力 |
| 配置中心 | Spring Cloud Alibaba 2025.1.0.0 + Nacos Client 3.1.1 | 本地调试连接本机 Nacos，服务器环境使用服务器 Nacos |
| 业务数据库 | MySQL | 保存正式业务事实和审计数据 |
| 缓存与短期状态 | Redis | 不保存正式文件、意见和唯一业务事实 |
| 文件存储 | MinIO | 保存原始文件、不可变版本、大体积上下文和模型原始结果 |
| 通用检索 | 独立 `rag-service` | AgentTo 只通过稳定服务接口访问，不直接查询 RAG 索引 |
| 模型提供方 | 第一版 DeepSeek | 通过兼容接口调用，保留千问、GLM 等适配口 |
| 工作流 | 后续独立 `workflow-service` | 重构复用 HopFresh BPM，不直接依赖完整 HopFresh 系统 |
| 本地开发 | 本地只运行前后端 | MySQL、Redis、MinIO、Elasticsearch 等连接阿里云现有服务 |

### 2.1 配置原则

- 业务配置、服务地址、模型参数和密钥统一由 Nacos 管理。
- 仓库只保留 Nacos 连接所必需的启动参数，不保存正式密码和密钥。
- 本地和服务器使用不同 namespace，避免调试配置影响正式环境。
- Spring Cloud Alibaba 2025.1.x 使用 `spring.config.import` 导入 Nacos 配置，不再使用 `bootstrap.yml`。
- DeepSeek 第一版可以直接使用，但模型调用必须经过统一接口，业务代码不能绑定某一家模型。

### 2.2 测试原则

- 纯业务规则使用单元测试，不依赖外部服务。
- 数据库、Redis、MinIO、Nacos、RAG 和模型适配使用集成测试。
- 集成测试连接真实开发环境中间件，不使用 H2 代替 MySQL。
- 测试使用独立数据库、独立 MinIO bucket 和 Redis key 前缀，避免污染人工验证数据。
- 每个阶段先补测试，再实现功能；阶段结束前统一执行完整回归。

## 3. 阶段 0：基础环境校正

### 目标

把现有 `backend` 骨架调整为后续可以稳定开发的基础工程。该阶段不开发具体 Agent 业务，也不固化流程流转规则。

### 主要工作

- 将 Spring Boot 从 4.1.0 调整为 4.0.x，并接入 Spring AI 2.0.0、Spring Cloud Alibaba 和 Nacos。
- 删除 H2 依赖和 H2 测试配置。
- 后端端口固定为 `18472`，避开常用的 8080 端口和 RAG 后端的 `18473`。
- 通过本机 Nacos 读取开发环境的 MySQL、Redis、MinIO 和模型配置。
- 建立真实 MySQL、Redis、MinIO 的基础连通性测试。
- 统一健康检查、启动、停止、状态检查和开发数据清理脚本。
- 修正文档中 Maven、端口、测试方式和本地部署方式的旧说明。

### 完成标准

- 使用 `D:\DevTools\Maven\bin\mvn.cmd` 可以完成构建和测试。
- 本地不启动 Docker 中间件，只启动 AgentTo 后端即可连接开发环境资源。
- `GET /actuator/health` 能反映 MySQL、Redis、MinIO 和 Nacos 的实际状态。
- Flyway 在真实 MySQL 测试库完成迁移，应用可重复启动。
- 仓库中不存在 H2 和明文密钥。
- 有一套明确的启动前检查，避免频繁启动后才发现配置或端口问题。

详细步骤单独记录在：`docs/superpowers/plans/2026-07-16-agentto-backend-phase-0-foundation.md`。

## 4. 阶段 1：账号、文件任务和版本基础

### 目标

先建立 Agent 运行所依赖的正式业务对象。即使暂时没有真实工作流，也能创建文件任务、确定处理人、上传新版本并保存完整历史。

### 主要工作

- 平台自有账号、部门和角色管理；
- 登录会话和接口权限；
- 文件任务、主导人、参与人和当前处理阶段；
- Word、PDF 主文件和 Excel 辅助材料上传；
- 文件版本不可覆盖，保存 SHA-256、上传人、时间和对象存储位置；
- 审计事件统一记录；
- 为后续企微身份映射预留外部用户 ID 和组织 ID。

### 暂不包含

- 不实现企微登录；
- 不实现 Flowable 流转；
- 不实现在线编辑和在线批注；
- 不让 Agent 修改或上传文件。

### 完成标准

- 技术管理员可以维护账号和组织数据；
- 文件主导人可以建立任务并上传文件；
- 同一任务的多个版本均可追溯、下载和校验；
- 不同角色只能访问自己有权查看的任务和文件；
- 删除入口默认关闭，正式记录不会被自动清理。

## 5. 阶段 2：RAG 服务接入和正式解析快照

### 目标

让 AgentTo 使用独立 RAG 服务完成解析和检索，同时保留自己的正式业务记录，不把审批事实交给 RAG 管理。

### 主要工作

- 为 RAG 增加面向业务系统的服务接口，不直接复用技术管理端接口；
- AgentTo 提交文件版本进行解析，记录 RAG 文档 ID、版本 ID、任务 ID 和 Trace ID；
- 查询解析进度、分块结果和失败原因；
- 解析成功后生成 AgentTo 正式解析快照；
- 检索接口返回 chunk、来源位置、分数、参数和 Trace；
- 设计幂等、超时、重试和服务不可用时的处理方式。

### 边界

- RAG 保存解析、分块、向量和检索 Trace；
- AgentTo 保存文件版本与解析结果的正式关联、使用记录和快照哈希；
- AgentTo 不直接访问 Elasticsearch；
- RAG 不理解 A、C、秘书组和老板等业务角色。

### 完成标准

- 从 AgentTo 提交一个文件后，可以看到解析的完整进度；
- AgentTo 可以按文件、知识范围和权限条件发起检索；
- 每条检索依据都能回到原文件、页码或结构位置；
- RAG 失败不会破坏原始文件和业务任务。

## 6. 阶段 3：模型、Prompt 和 Agent 定义管理

### 目标

先把“用哪个模型、以什么角色、按照什么要求分析”管理起来，再进入真正的 Agent 执行。

### 主要工作

- 模型提供方、模型名称、参数和密钥引用；
- DeepSeek 适配器及统一 `ChatModelGateway`；
- 为千问、GLM 预留同一套适配接口；
- Prompt 草稿、发布版本、变量定义、差异和回滚；
- Agent 定义、适用角色、执行策略、知识范围和功能开关；
- 主导人自审 Agent 和秘书组终审 Agent 的第一套配置；
- Prompt 预览和变量来源检查。

### 完成标准

- 模型和 Prompt 可以不改代码完成切换；
- 已发布 Prompt 版本不可被直接覆盖；
- 能预览基础模板，但尚未执行正式 Agent；
- 密钥不会进入接口响应、日志或数据库明文字段。

## 7. 阶段 4：动态上下文和 Agent Runtime

### 目标

完成第一条真正的 Agent 分析链路，并保证运行过程、输入和结果都可复现。

### 主要工作

- 构建不可变 `ContextPackage`；
- 纳入当前文件、附件、角色、目标、当前轮次、全部历史文件和历史意见；
- 调用 RAG 获取知识依据，并锁定 chunks、参数和 Trace；
- 使用已发布模板生成最终 Prompt；
- 第一版默认完整传入三轮以内的上下文，不做强制压缩；
- 超出模型上下文时继续按实际行为执行并明确记录警告，不静默截断；
- 实现 Planning、Review、Reflection、Finalize 四阶段；
- 使用持久化运行状态和 SSE 进度；
- 支持取消、失败重试、幂等和并发控制；
- Agent 失败不阻塞人工任务流转。

### 完成标准

- 主导人可以手动触发自审 Agent；
- 秘书组可以手动触发终审 Agent；
- 同一任务、轮次和 Agent 类型不会产生两个并行正式运行；
- 每次运行都能还原 ContextPackage、最终 Prompt、模型参数和原始响应；
- Agent 不修改文件、不提交正式意见、不推进流程。

## 8. 阶段 5：全过程可视化和人工反馈

### 目标

让业务使用者看到适合自己角色的结论，让技术管理员看到完整执行细节。

### 主要工作

- 运行列表、状态时间线和阶段耗时；
- ContextPackage 来源树；
- Prompt 模板、变量、最终 Prompt 和版本差异；
- 每次模型调用的输入摘要、输出、Token、耗时、错误和重试；
- RAG 检索依据、分数和 Trace 跳转；
- 结构化问题、证据、建议和风险等级；
- 人工采纳、忽略、修正和备注；
- 角色化数据权限：主导人结果只给主导人，秘书组结果先只给秘书组；
- 技术管理员能够查看完整运行链路，但敏感字段仍受权限控制。

### 完成标准

- 业务人员不需要理解技术细节也能使用 Agent 结果；
- 技术管理员可以定位一次运行慢在哪里、失败在哪里、使用了什么输入；
- 所有反馈和后续重新运行都保留历史，不覆盖旧记录。

## 9. 阶段 6：临时流程适配层

### 目标

在正式 BPM 迁移前，验证文件、意见、Agent 和角色之间能形成完整业务闭环，同时不把临时规则写死进核心模块。

### 暂定流转

文件主导人自审 → 全部 C 提交咨询意见 → 秘书组终审 → 老板审批。

暂定退回后重新开始一轮，完整经过自审、全部 C 审查、秘书组终审和老板审批。具体退回条件、咨询意见与退回的关系、C 是否必须全部完成等，仍以总经办确认结果为准。

### 实现边界

- 所有流转操作只调用 `WorkflowGateway`；
- Agent 模块只读取规范化 `WorkflowContext`，不认识临时流程实现；
- 事件统一使用 `WorkflowEvent`，为后续外部工作流服务留好接口；
- 临时实现可以被关闭或替换；
- 不建设第二套与 Flowable 重复的通用流程设计器。

## 10. 阶段 7：独立工作流服务

### 目标

基于 HopFresh BPM 已验证的能力，重新形成与 AgentTo 技术栈和边界一致的独立 `workflow-service`。

### 主要工作

- 迁移必要的流程模型、定义、实例、任务、表单和历史能力；
- 迁移审批、驳回、退回、转办、委派、加签、减签和撤回等必要动作；
- 去除 HopFresh 中与本项目无关的业务模块和平台耦合；
- 适配 AgentTo 的账号、部门、权限和审计；
- 接入公司已有的企微通知代码；
- 通过稳定 API 和事件与 AgentTo 交互；
- 工作流不可用时，AgentTo 正式业务数据仍保持完整。

Flowable 版本、需要迁移的原生表和扩展表，要在迁移计划中根据 HopFresh 源码和数据库脚本再次确认，不在当前阶段提前定死。

## 11. 后续能力

以下能力保留接口，但不作为前几个阶段的前置条件：

- 消息队列替换第一版数据库任务调度；
- Tool/MCP，只允许只读能力并默认关闭；
- 多模型对比实验；
- 上下文摘要、压缩和分层记忆；
- OCR 和复杂扫描件处理；
- 企业微信登录和移动端；
- 电子签名、数字签章和防篡改证明；
- 服务拆分部署和独立扩缩容。

## 12. 当前不进入开发的内容

- 总经办尚未确认的具体退回、会签和终审规则；
- C 阶段 Agent；
- 在线编辑和在线批注；
- Agent 自动修改文件；
- Agent 自动提交意见或代替审批；
- 直接改造完整 HopFresh 系统；
- 将正式上下文只保存在 Redis；
- 把 RAG、工作流和 AgentTo 的业务表混在一起。

## 13. 计划维护方式

- 本文只维护总体顺序和阶段边界。
- 每次只为即将开始的阶段编写详细实施计划。
- 详细计划必须写清文件路径、接口、测试、执行命令和验收方法。
- 业务规则发生变化时，先判断属于 BPMN 调整、配置调整还是核心业务模型变化，再决定修改范围。
- Spring Boot、Spring AI、Spring Cloud Alibaba 和 Nacos 的版本升级要单独验证，不能在业务功能开发过程中顺手升级。
